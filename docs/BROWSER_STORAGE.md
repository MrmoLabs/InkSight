# 浏览器工作区存储

浏览器版通过原生 IndexedDB 保存工作区，数据库名为 `inksight-runtime`。
Electron 桌面版继续使用本机目录和原有 IPC 文件格式。

## 数据组织

数据库版本 2 使用以下对象仓库：

| 仓库 | 内容 |
| --- | --- |
| `runtime-snapshots` | 工作区清单、画布和标注数据、文件引用，以及当前快照指针 |
| `snapshot-meta` | 历史列表摘要、快照记录位置和引用的文件键 |
| `snapshot-binaries` | 以 SHA-256 为键保存的文件内容，可跨快照、跨项目共用 |
| `files` / `md5-index` | 保留现有的单文档恢复记录与查询索引 |

文件路径、类型等属性保存在快照引用中。因此，同一内容即使在不同项目中使用不同名称或类型，也能共用二进制存储。
历史列表和淘汰逻辑只读取摘要，不再全量读取快照正文或文件内容。
读取选定快照及其文件使用同一个只读事务，避免其他标签页清理历史时打断恢复。

每个项目仍保留最多 20 份快照。新快照、文件写入、旧快照淘汰及未引用文件删除在同一个事务内提交；失败时整体回滚。
清理文件前会检查所有项目保留快照的引用，不会删除其他项目仍需使用的文件。

## 自动保存

自动保存仍按配置的间隔检查工作区，但只有内容或项目文件发生变化才创建快照。
检查包含画布、视图状态、标注、卡片、图谱数据、文档元数据和项目文件身份，不会为检查变化重新读取文档原文件。
同名同大小的替换文件仍会被识别为变化。
保存期间发生的新编辑会留到下一次自动保存；失败的保存不会把工作区标记为已保存。
手动保存和手动创建快照不受跳过规则影响。

浏览器保存直接传递 Blob/File；不可变文件对象的哈希通过弱引用缓存，同一会话中再次保存无需重新读取该文件。
首次出现的文件仍需读取并计算 SHA-256。该功能需要提供 Web Crypto 的环境，例如 HTTPS 或 localhost。
阅读位置继续通过原有轻量历史记录保存。

## 旧数据升级

首次打开旧库时，版本升级逐条建立摘要索引，并将旧的内嵌当前快照规范化为历史记录及指针。
旧快照在去重转换前仍可正常恢复。

成功保存新快照后，旧快照逐份转换为文件引用，每份转换单独提交并在记录之间让出执行时间。
转换失败的旧记录保留原内容，下次保存重试。迁移不改变当前快照，也不单独触发历史淘汰。
现有 20 份保留策略只在创建新快照时执行。

本次改动不提供容量上限、手动快照永久保留策略或新的存储清理界面；“重置工作区”也仍不等于删除所有历史项目。
数据库记录减少后，浏览器配置目录的实际磁盘体积由浏览器后续压缩和回收决定，不保证立即同比下降。

## 验证

- `npm test -- --run`：包括模拟 IndexedDB 的跨项目去重、保留与回收、旧库升级、保存失败回滚，以及自动保存变化检测。
- `npm run test:storage:browser`：在隐藏的 Electron Chromium 窗口中运行真实 IndexedDB 测试，使用 `.runtime/storage-browser-smoke` 下的独立配置目录和临时 localhost 来源，不访问用户的工作区。
  该检查验证 32 MiB 文件、20 份保留快照只存一份二进制内容、旧库转换、刷新恢复，以及完整项目 IO 的文档和图片恢复。进程退出后自动删除本次测试配置目录。
- `npm run build`：验证生产打包。
